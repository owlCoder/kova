# Delivery plan and acceptance gates

Architecture is **approved with [amendments](REVIEW-CHANGES.md)**. Implement milestone 1 only; stop after its report until the user confirms milestone 2. Status labels are honest: milestone status reflects observed acceptance evidence.

| Stage                     | Scope                                                                                                                                                             | Acceptance gate                                                                                                                                          | Status                                |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| 0 — Architecture          | ADRs, package tree, contracts, state machine, protocol, budgets, security model, test plan                                                                        | Full scaffold checks pass and human architecture review                                                                                                  | Accepted                              |
| 1 — Foundation/chat       | Extension manifest/activation/sidebar; React Webview; Ollama discovery/stream/cancel; explicit num_ctx; thinking/usage; Core context/conversation implementations | Installed models; streamed qwen3:4b; working Stop; offline after model install; no Core framework/provider dependency; unavailable runtime handled       | In progress                           |

| 3 — Editing               | write/edit; path guard; protected-path guardrail; computed diff; Manual/Edit approval; editor undo                                                                | Containment and realpath tests; exact one-match edit; approval deny/no write; stale approval/new preview; protected writes approve every mode            | Planned                               |

| 7 — ERS teaching          | Actual ERS MCP and guardrail adapter; review skill; walkthrough                                                                                                   | Recorded real review/diff/test flow and blocked unsafe operation                                                                                         | Awaiting example-project availability |

Minimal containment/protected-write guardrails are implemented in milestone 3, before editing. The fuller pluggable pipeline and Auto/process work come in milestone 6. Until then Auto is disabled with visible milestone status, rather than behaving like a less protected Edit mode. Core contracts define all four final modes now; the final product has exactly those four.

At every milestone, run relevant behavior/integration tests plus the full typecheck/lint/architecture/format suite. Record implemented behavior, observed acceptance evidence, deviations from ADRs and remaining risks. Do not introduce broad runtime stubs merely to populate the planned tree. Pin runtime dependencies at the milestone that first uses them.

Distribution is separate from development: extension identity/logo/name and trademark review, license choice, Marketplace packaging and publication need their own concrete request/review. This phase creates the GitHub repository and pushes the architecture baseline, without publishing an extension.
